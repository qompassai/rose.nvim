# Local web UI

Rose can serve a small browser front end from inside Neovim. It is a plain
HTTP/1.1 server written on `vim.uv` TCP handles: no plugin, no Node process, no
bundled assets, no network access beyond the loopback interface. The page is a
single self-contained HTML document generated by `lua/rose/webui/page.lua`.

The web UI is **off by default**. Nothing listens until `webui.enabled = true`
and `:RoseWebUI` is run (or `webui.open` starts it during setup).

## Setup

```lua
require("rose").setup({
  webui = {
    enabled = true,       -- master gate; false refuses :RoseWebUI
    host = "127.0.0.1",   -- loopback only; "::1" and "localhost" also accepted
    port = 0,             -- 0 = random free port chosen by the kernel
    open = true,          -- open the URL with vim.ui.open on first start
    max_request_bytes = 16 * 1024 * 1024,
    max_clients = 8,
    idle_timeout_ms = 30000,
  },
})
```

| Command            | Effect                                                             |
| ------------------ | ------------------------------------------------------------------ |
| `:RoseWebUI`       | Start the server (idempotent) and print the tokenised URL.         |
| `:RoseWebUIStop`   | Stop listening and close every client socket.                      |
| `:RoseWebUIStatus` | Print `running`, bound address, port, live clients, requests served. |

The URL looks like `http://127.0.0.1:41823/?token=3f9c...`. Copy it exactly:
the token is the credential. Closing Neovim (`VimLeavePre`) stops the server.

## Security model

- **Loopback only.** `webui.host` must resolve to `127.0.0.1`, `::1`, or
  `localhost`; any other address fails validation before a socket is created.
- **Per-session bearer token.** Sixteen random bytes from `uv.random`, hex encoded,
  generated on every start. Every `/api/*` request must carry it as
  `Authorization: Bearer <token>` or `?token=<token>`; otherwise the server
  answers `401`. `GET /` (the inert page) needs no token, but the page itself
  cannot call the API without the token from its own URL.
- **One request per connection.** Every response carries `Connection: close`;
  there is no keep-alive, pipelining, upgrade, or chunked request support.
- **Content-Length required.** `Transfer-Encoding: chunked` and missing lengths
  are rejected with `411`; oversized bodies with `413`.
- **Response hardening.** `Cache-Control: no-store`, `X-Content-Type-Options:
  nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, and a CSP of
  `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline';
  connect-src 'self'; media-src blob:; img-src data:`.
- **No filesystem exposure.** The only static route is `GET /`. There is no
  directory listing, no path mapping, no file serving.
- **Temporary audio.** Uploaded audio is written under
  `stdpath("cache")/rose/webui` with mode `0600`, passed to `rose.speech`, and
  unlinked when the request completes (also on error).

## Routes

| Method | Path                     | Token | Body                                      | Success response                                                     |
| ------ | ------------------------ | ----- | ----------------------------------------- | -------------------------------------------------------------------- |
| GET    | `/`                      | no    | none                                      | `text/html; charset=utf-8`, the page                                 |
| GET    | `/api/health`            | yes   | none                                      | `{ok, clients, requests_served, uptime_ms}`                          |
| GET    | `/api/state`             | yes   | none                                      | `{config, limits, provider, flow, speech}`                           |
| POST   | `/api/chat`              | yes   | `{"messages":[{role, content}, ...]}`     | `{message: {role: "assistant", content}, provider, model, ...}`      |
| POST   | `/api/flow/run`          | yes   | `{"task": "..."}`                         | Flow report JSON, or `503` when Flow is not configured               |
| POST   | `/api/speech/transcribe` | yes   | raw audio with audio `Content-Type`, or `multipart/form-data` | `{text, ...}` from `rose.speech.transcribe`      |
| POST   | `/api/speech/speak`      | yes   | `{"text", "provider"?, "voice"?}`         | audio bytes with the mime reported by `rose.speech.speak`            |

`provider` in `/api/state` comes from `rose.native.model.describe`; `flow` reports
`available`, `cmd`, `executable`, `connected`, `bridge`; `speech` is
`{available=false, reason}` when `rose.speech` cannot be required, else
`{available=true, enabled, capabilities}` from `rose.speech.capabilities()`.

Chat is routed through `rose.native.model.chat(fullconfig, messages, nil, cb)`,
which is the same path the editor uses, so provider consent rules
(`providers.enabled`, `providers.allow_cloud`) apply unchanged.

### Status codes

| Code | Meaning                                                         |
| ---- | --------------------------------------------------------------- |
| 400  | Malformed request line, header, JSON, or multipart body         |
| 401  | Missing or wrong token                                          |
| 404  | Unknown path                                                    |
| 405  | Known path, wrong method                                        |
| 408  | Client idle longer than `idle_timeout_ms`                       |
| 411  | Missing `Content-Length` or chunked transfer encoding           |
| 413  | Body larger than `max_request_bytes` or `audio_bytes_max`       |
| 415  | Unsupported `Content-Type`                                      |
| 431  | Headers exceed `header_bytes_max` or `header_count_max`         |
| 500  | Handler raised an error                                         |
| 502  | Provider or speech backend returned an error                    |
| 503  | Too many clients, or Flow / speech unavailable                  |
| 504  | Handler exceeded `handler_timeout_ms`                           |

## Limits

Configurable (validated in `require("rose.webui").validate`):

| Key                 | Default    | Range                 |
| ------------------- | ---------- | --------------------- |
| `port`              | `0`        | 0 .. 65535            |
| `max_request_bytes` | 16 MiB     | 4096 .. 256 MiB       |
| `max_clients`       | `8`        | 1 .. 64               |
| `idle_timeout_ms`   | `30000`    | 100 .. 600000         |

Fixed protocol constants (`require("rose.webui.server").limits`):

| Constant                   | Value    | Purpose                                     |
| -------------------------- | -------- | ------------------------------------------- |
| `header_bytes_max`         | 8192     | Whole header block                          |
| `header_count_max`         | 64       | Header lines                                |
| `request_target_bytes_max` | 2048     | Request path + query                        |
| `query_params_max`         | 32       | Query pairs                                 |
| `handler_timeout_ms`       | 3600000  | Hard ceiling; providers time out sooner     |
| `chat_messages_max`        | 64       | Messages per `/api/chat`                    |
| `flow_task_chars_max`      | 8192     | Task length for `/api/flow/run`             |
| `speak_text_chars_max`     | 4096     | Text length for `/api/speech/speak`         |
| `audio_bytes_max`          | 25 MiB   | Upload for `/api/speech/transcribe`         |
| `multipart_parts_max`      | 8        | Parts in a multipart upload                 |
| `token_bytes`              | 16       | Random bytes in the session token           |
| `listen_backlog`           | 16       | Kernel accept queue                         |

## Page behaviour

- Header pills show provider/model, Flow, and speech state from `/api/state`.
- **Dictate** records with `MediaRecorder` (60 s cap), posts the blob to
  `/api/speech/transcribe`, and appends the text to the prompt.
- **Speak** posts the prompt (or last assistant reply) to `/api/speech/speak` and
  plays the returned audio from a blob URL.
- Both buttons disable themselves with a `title`/hint explaining why when speech
  is unavailable, no engine is present, or the browser lacks `MediaRecorder`.
- The Flow panel posts a bounded task and renders the report; the health drawer
  shows `/api/health` and `/api/state` JSON.

## Boundaries

- **No TLS.** Traffic is plaintext on loopback only; do not port-forward it.
- **Loopback only.** Binding to any non-loopback address is refused.
- **One Neovim instance per server.** Each instance owns its own port and token;
  the page talks to the instance that opened it.
- **No streaming.** Chat responses are returned once complete.
- **No persistence.** Transcript state lives in the browser tab.
- **Token in the URL.** The URL grants API access for the session; do not paste
  it into shared logs or issue reports.

## Testing

```sh
ROSE_TEST_PYTHON=python3 nvim --headless -u NONE -l tests/webui.lua
```

`tests/webui.lua` drives the server with `tests/webui_client.py` (stdlib only)
and stubs `rose.native.model`, `rose.native.flow`, and `rose.speech` through
`package.loaded`, so no provider, Flow binary, or speech engine is needed.
